# Версионная история дивидендных событий

Реализация: `dividend_events/`, схема `1.0.0`. ТЗ:
[moexutils-dividend-events-request.md](moexutils-dividend-events-request.md).

## Что предоставляет модуль

Сбор фиксирует объединённый реестр из маппинга, всех `data/raw/*.csv` и
`data/*.csv`, `combined_stocks.csv`, переименований и делистинга moexutils,
полных страниц MOEX ISS отдельно для активных и неактивных бумаг.
Каждый выпуск получает строку coverage, включая ошибки и неподдержанные источники.
Акции и расписки включены; другие инструменты отражены в classification.
Неопределённые локальные тикеры сохраняются с `identity_status=unresolved`.

`security_id` строится из ISIN и регистрационного номера. Старые/новые тикеры
одного выпуска сохраняются как алиасы. Переименование из moexutils само по себе
не объединяет юридически разные выпуски: например, редомициляция требует проверки.
Неизвестные интервалы алиасов, юрисдикция и соотношение расписок остаются NULL.
Отсутствие в текущем маппинге фиксируется отдельно от статуса торгов.

Первичные байты HTML/JSON/PDF и прочих ответов хранятся без преобразования,
по SHA-256. HTTP-метаданные ограничены Content-Type, Last-Modified, ETag, Date,
Content-Length. Cookies и заголовки авторизации не записываются.
Сохранение PDF не означает автоматического извлечения фактов из него.

## Запуск

```powershell
pip install -r requirements-events.txt

python -m dividend_events backfill --run-id initial-20261015 `
  --moexutils F:/Yandex.Disk/FINANCE/moexutils `
  --sources metadata/official_history_sources.json `
  --start 2023-01-01 --end 2026-10-05
```

По умолчанию артефакты записываются в `artifacts/dividend-events`, исключённый
из Git. Для внешнего большого хранилища задайте `--root PATH` либо переменную
`DIVIDENDS_EVENTS_ROOT`. Новая БД и планировщик не нужны.

`--run-id` фиксирует входной реестр, параметры и контрольные точки. Повтор той
же команды продолжает незавершённые бумаги. Для расширения периода, изменения
источников или повторной проверки ошибок используйте новый run-id.
`--offline` запрещает сеть и использует только сохранённые ответы; пропуски кэша
отражаются как ошибки источников. Список бумаг не уменьшается из-за таких ошибок.

Для получения новых редакций:

```powershell
python -m dividend_events update --run-id update-20261016 `
  --previous artifacts/dividend-events/packages/PACKAGE_ID `
  --moexutils F:/Yandex.Disk/FINANCE/moexutils `
  --sources metadata/official_history_sources.json
```

`update` требует предыдущий закреплённый пакет и сохраняет его выпуски,
документы и события. Однозначные изменения одного источника в рамках одного
дивидендного эпизода получают `supersedes_id`. Неоднозначные совпадения сохраняются
отдельно; дата реестра не используется как единственный ключ.

Пауза по умолчанию 2 секунды, таймаут 25 секунд, до двух повторов сетевых ошибок.
Можно задать `--delay`, `--timeout`, `--retries`; для агрегатора выдерживается
не менее 2 секунд даже при меньшем `--delay`. HTTP 401/403/429 не обходятся
и не повторяются внутри запроса. HTTP 200 без нужной таблицы — ошибка формата,
а не подтверждение отсутствия выплат.

## Источники и фактические ограничения

| Источник | Использование | Ограничение |
|---|---|---|
| MOEX ISS securities, active/inactive | Идентичность и universe | Не подтверждает полноту старых раскрытий |
| Старые CSV | Сверка, сохранение истории | Нет даты публикации и доказательства базы акции |
| ЗакрытияРеестров.рф | `reference/unverified`, исходный HTML каждой строки | Исключён из обоих строгих режимов чтения |
| Официальная история Норникеля | Решения, объявленная сумма, дата реестра, опубликованный срок | Текущая страница, историческая редакция не доказана |
| Официальная история ЛУКОЙЛа | Объявленная сумма и дата реестра | Нет доказательства времени публикации и редакции |
| e-disclosure | Документы/архивы по настроенным адресам | При проверке 15.10.2026 HTTP 403 |
| Газпром, настроенный официальный релиз | Сохранение документа при доступности | При проверке ошибка доверия TLS; проверка сертификата не отключается |
| СКРИН, регулируемая лента | Поиск по ИНН всего идентифицированного реестра, решения, начисления, выплаты, поправки | Поиск за скользящий год; исторические прямые ссылки доступны |
| ПРАЙМ, регулируемая лента | Полная пагинация поиска по ИНН за заданный период, исторические тексты | Большой объём облигационных сообщений; нестандартные категории отмечаются как непрочитанные |
| Прочие официальные документы | Настраиваемые URL и проверенный импорт фактов | Неподдержанные формулировки и документы остаются на явной проверке |

Архивные адаптеры используют весь зафиксированный реестр, а не список двух
официальных таблиц. Неопределённые идентичности выпусков, непрочитанные документы,
ошибки и ограничения поиска остаются в coverage. Наличие HTTP 200, исчерпание
страниц или совпадение суммы не доказывают полноту 2023–2026.

`available_from/to` в архивном покрытии — найденные даты публикаций. Если их
нет, сохраняется глубина прежних источников по датам реестра; тип отмечен
в `available_date_kind` внутри `reasons_json`. Это не гарантированная
непрерывная глубина архива. Старые и новые строки вне запрошенного интервала
сохраняются. Конечная дата запроса не обрезает историю: снимок задаётся чтением
`as_of`, новые публикации после неё не должны попадать в ранний ответ.

## Схема и семантика

Точные поля/типы закреплены в `dividend_events/schema.py` и копии `schema.json`
внутри каждого пакета. Таблицы:

- `securities`: выпуск, эмитент, ISIN, регномер, класс, алиасы, статус идентичности.
- `events`: эпизод, версия, предыдущая версия, тип/статус, сумма, время,
  права, условия/подтверждение выплаты и доказательства.
- `sources`: URL, ID, байты, хеш, получение и безопасные HTTP-метаданные.
- `coverage`: каждый выпуск, интервал запроса, глубина, счётчики, причины пробелов.
- `conflicts`: конфликтующие версии и расхождения реестров корпоративных действий.
- `corporate_actions`: закреплённые реестры dividends/moexutils без молчаливого согласования.
- `reconciliation`: все строки прежних CSV с `matched/differs/no_confirmation`.
- `classification`: включённые, исключённые и спорные инструменты.

Суммы — десятичные строки для точности, NULL требует `amount_unknown_reason`.
Ноль допускается как подтверждённое числовое значение; `no_dividend` — отдельное
решение. Рекомендация не платить кодируется `recommendation/proposed` с нулём,
а не утверждённым решением. `cancellation` требует связи с отменённым событием.
`paid` требует доказательства и фактической даты, частичный платёж отмечается
`partial_payment`. Опубликованный срок не означает наступивший платёж.

Объявленная сумма не меняется при сплитах. `normalized_amount` возвращает
отдельное значение, коэффициент, целевую дату и IDs корпоративных действий.
Для применения нужны подтверждённые действия, их время известности и исходная
дата базы акции. Входные реестры сейчас `unverified`; они не применяются к событиям.
Конвенция `auto` moexutils сохраняется как есть и не переинтерпретируется.

Расчёт ex-date/last-buy-date остаётся за moexutils. Импортированные расчётные
даты требуют `derived`, закреплённого календаря и правила расчётов. Календарные
дни из даты реестра автоматически не вычитаются.

## Причинное чтение

```python
from dividend_events import read_as_of

events = read_as_of(
    "artifacts/dividend-events/packages/PACKAGE_ID",
    "2026-10-05T23:59:59.999999+03:00",
    mode="public_as_of",
)
```

Чтение проверяет хеши пакета, не открывает сеть и не обращается к текущим CSV.
Timestamp без часового пояса отклоняется. Режимы:

- `public_as_of`: только `verified` и доказанная публичная доступность конкретной
  редакции. Требуются `published_at`, `publication_evidence`, `edition_evidence`
  и `historical_availability=proven`.
- `observed_as_of`: проверенные факты после первого получения нашим сборщиком.
  Не требует исторического доказательства редакции. Строки агрегатора
  `reference_only` по-прежнему исключены.

Точность `day` означает доступность с начала следующего дня в указанном IANA
часовом поясе. `hour` и `minute` используют окончание соответствующего интервала.
Дата решения не подставляется в published_at; загрузка не заменяет публикацию.
Поздно найденный документ может попасть в ранний public-as-of только при
отдельном доказательстве исторической редакции. Текущий HTML со старой датой
этому условию не соответствует.

Сначала отбираются известные версии, затем разрешаются связи supersedes.
Позднее исправление не меняет ранний ответ. Несвязанные конфликтующие версии
возвращаются обе; потребитель обязан рассмотреть conflicts, а не выбирать
последнюю по положению в таблице. `state=False` возвращает все известные события.

```powershell
python -m dividend_events validate artifacts/dividend-events/packages/PACKAGE_ID
python -m dividend_events export artifacts/dividend-events/packages/PACKAGE_ID `
  --at 2026-10-05T23:59:59.999999+03:00 --mode public_as_of `
  --output artifacts/public-20261005.parquet
```

Экспорт поддерживает Parquet/JSON, повтор идентичного результата идемпотентен.
Отличающийся существующий файл не перезаписывается. Старый CSV-формат продолжает
формироваться прежним парсером; новые рекомендации в него не экспортируются.

## Добавление подтверждённых фактов

`--sources FILE.json` — массив записей с `ticker` или `security_id`, `url`,
необязательным `adapter`. Доступные адаптеры: `nornickel_history_v1`,
`lukoil_history_v1`. Они проверяют ISIN и ожидаемую структуру, при изменении
вёрстки возвращают ошибку вместо догадки. Без адаптера сохраняется документ
для разбора; факт автоматически не создаётся.

`--reviewed FILE.json` — массив явно проверенных фактов. Запись содержит:

```json
{
  "security_id": "security:IDENTIFIER_FROM_SECURITIES",
  "url": "https://issuer.example/official-announcement",
  "dividend_key": "2023:annual:ordinary",
  "supersedes_id": null,
  "fields": {
    "event_type": "approval",
    "status": "approved",
    "amount": "10.25",
    "amount_basis": "gross",
    "currency": "RUB",
    "reporting_period": "2023 full year",
    "verification_status": "verified",
    "historical_availability": "unproven",
    "publication_precision": "unknown",
    "evidence": "EXACT EXCERPT FROM THE SAVED DOCUMENT"
  }
}
```

Это пример структуры, не реальные данные. Вместо скачивания можно передать
`raw_file`; observed_at будет временем импорта, а не датой файла. Фрагмент
проверяется на наличие в сохранённом HTML/тексте. Семантическую точность суммы,
идентичности и доказательства исторической редакции обеспечивает проверяющий.
Импорт бинарных PDF-фактов без извлечённого и проверенного текста не поддержан.

## Неизменяемость, сверка и передача

Пакет содержит manifest/summary, их отдельные `.sha256`, все таблицы, схему и
использованные raw-файлы. Manifest перечисляет хеши артефактов, версию схемы,
парсера, Git HEAD и фактические хеши модулей, запрошенные/найденные границы,
политику времени и хеш universe. Существующий каталог не перезаписывается.
SHA-256 проверяет целостность, но не заменяет доверенную внешнюю подпись пакета.

Сверка консервативна: совпадение суммы/даты без периода и подтверждённой базы
акции недостаточно. Скорректированные CSV не сравниваются напрямую с суммой
объявления. Поэтому `no_confirmation` не означает ошибку CSV.

moexutils получает точный путь/package_id и хеш manifest, проверяет пакет,
добавляет торговые календари и сведения о фьючерсах. futures-analytics использует
закреплённые данные без самостоятельного скачивания рынка.

## Проверки

```powershell
pip install pytest
python -m pytest -q --basetemp artifacts/test-tmp
```

Тесты используют явно синтетические документы. Проверяются рекомендация →
утверждение, поправки, отмена, отдельное no_dividend, частичные выплаты,
неизвестная публикация/редакция, точность времени, public/observed, конфликты,
сплит без изменения исходной суммы, префы, сохранение алиасов/делистинга,
разные выплаты на одну дату, повтор импорта и нарушение целостности пакета.
Реальные примеры строгого public-as-of нельзя заявлять выполненными,
пока архивные доказательства публикации и редакции не получены.

## Регулируемые архивы СКРИН и ПРАЙМ

Сборщик `dividend_events.archive` связывает зафиксированные выпуски с ИНН из
сырого реестра MOEX. Поиск и загрузка возобновляются по отдельным контрольным
точкам эмитентов и сообщений; результаты разбираются заново при сборке пакета.
Неоднозначный выпуск, неподдержанная формулировка или несвязанная корректировка
попадают в очередь проверки. Полный исходный текст остаётся в raw.

```powershell
python -m dividend_events.archive --previous <закреплённый-пакет> --run-id prime-history --provider prime --start 2022-01-01 --end 2026-10-15 --phase all
python -m dividend_events.archive --previous <закреплённый-пакет> --run-id skrin-history --provider skrin --start 2022-01-01 --end 2026-10-15 --phase all
```

Фазы `index`, `documents`, `build` можно запускать последовательно. Повторять
с теми же `previous`, `start`, `end` и `run-id`; изменившиеся параметры требуют
нового run-id. Для одного провайдера разрешён один сетевой процесс. При серии
HTTP 503 сборщик временно прекращает запросы; непрочитанные документы явно
учитываются и могут быть получены повторным запуском. Для `build` сеть не нужна.

СКРИН предоставляет неизменяемые новостные сообщения по условиям §§3.6–3.9:
https://disclosure.skrin.ru/index.asp?id=61&fid=0. Его поисковая выдача ограничена
скользящим годом, хотя отдельные старые сообщения доступны по прямым ссылкам.
Поэтому исчерпание страниц не доказывает полноту запрошенной ранней истории.

ПРАЙМ позволяет искать сообщения за 2022–2026 годы. Правила требуют исправлять
новость отдельным сообщением и запрещают её удаление:
https://disclosure.1prime.ru/misc/faquser.aspx. На странице сообщения время
обычно указано до минуты; причинная граница — конец этой минуты. Секунды из
поисковой выдачи не подставляются вместо точности самого документа.

Это доказательство по договорным правилам регулируемого архива, а не внешняя
криптографическая отметка времени. Оно не распространяется на заменяемые
приложения эмитентов. Пакет закрепляет текст правил, ID сообщения, ИНН, время
и SHA-256 его смыслового текста; валидатор проверяет их повторно по raw.

Отчёт `archive_collection_report` закреплён как источник внутри пакета. Он
содержит запросы, найденные документы, ошибки, незагруженные сообщения и очередь
проверки. `archive_report_source_id` в manifest указывает на этот отчёт.
`history_complete=false` сохраняется: отсутствие найденной новости не означает
нулевого дивиденда. При подтверждённой выплаченной сумме и неизвестной дате
`actual_payment_date=NULL`, `gap_reason=actual_payment_date_not_disclosed`.

Поля стандартной формы начисленных доходов разбираются отдельно от итоговых
выплат. Однозначный опубликованный срок создаёт `payment_terms` с `payment_to`,
но не заполняет `actual_payment_date`. Несколько сроков разных категорий
получателей без однозначного разбора сохраняются в исходном тексте.

Явная ссылка исправления на архивный ID исходного сообщения позволяет создать
`amendment` с `supersedes_id`. Одно совпадение суммы, периода или даты реестра
такой связью не считается. Изменение текста под прежним неизменяемым ID
нарушает доказательство редакции: новая наблюдённая версия сохраняется, но
исключается из `public_as_of`.

Отчётный период сам по себе не является ключом выплаты: одна и та же старая
прибыль может распределяться несколькими собраниями. Адаптер связывает эпизод
по явно указанной дате собрания и периоду. Без такого основания он сохраняет
отдельный документный эпизод с `episode_linkage.basis=unresolved_document`
в `edition_evidence`; coverage считает `unresolved_episode_links`. Поправка с
явным ID исходного документа наследует его dividend_id. Условия, содержащие
зачёт ранее выплаченного дивиденда, и сообщения с непринятыми решениями
остаются на проверке контекста вместо автоматического утверждения суммы.

Для объединения провайдеров сначала собрать пакет одного архива, затем передать
его как `--previous` в офлайн-фазу `build` другого. Сетевые фазы продолжают
использовать исходные параметры своего run-id. `--workers` (1–4) перекрывает
ожидание ответов, сохраняя общую паузу `--delay` между запросами.

## Проверка реальных архивных примеров

```powershell
python -m dividend_events.audit --package <объединённый-пакет> --baseline <исходный-пакет-CSV> --output artifacts/dividend-events/audits/<package-id>
```

Аудит требует настоящую рекомендацию за каждый год 2023–2026 и связанную
архивную корректировку. Он проверяет состояние непосредственно до/после
публикации, отличие `observed_as_of`, неизменность раннего ответа после поздней
поправки и SHA-256 всех прежних CSV. JSON-отчёт содержит ссылки, хеши и пути
доказательств; Parquet-экспорты позволяют воспроизвести ответы. Повторный аудит
не перезаписывает отличающиеся результаты.

`read_many_as_of(package, requests)` проверяет пакет один раз и выполняет набор
запросов из одного снимка в памяти. Каждый запрос содержит `at`, необязательный
`mode` и `state`. Кэш разбора доказательств живёт только в пределах проверки;
следующая проверка заново проверяет хеши файлов.

## Повторное использование раскрытий для облигаций

Архитектурная оценка 15.10.2026 после просмотра соседних проектов: raw и receipts
пригодны для общего архива раскрытий. Метка `not_dividend` означает результат
дивидендного парсера и не удаляет документ. В то же время `out_of_scope_title`
означает только сохранённую поисковую запись: тело такого сообщения не загружено.
Существующий проход охватывает эмитентов акций, а не полный облигационный рынок.

В промежуточном пакете `dividends-2b86557b1b06146557930a53` уже сохранено 2 717
сообщений с признаком `explicit_bond_income_category` — кандидатов для такого
разбора, не готовых облигационных событий. Например, сообщение СКРИН
`eid=3759694&agency=1` содержит раскрытие МТС по RU000A10B1N3, 16-му купону,
сумме на облигацию и проценту исполнения. В одном документе также повторяется
история предыдущих купонов: нельзя считать каждую строку новым текущим платежом
или датировать всю эту историю временем одного сообщения.

`../moexutils/moexutils/cashflows.py` уже предоставляет графики купонов,
амортизации и оферт MOEX, включая погашенные выпуски. Их следует использовать
для календаря обязательств; дата потока и снимок DuckLake не доказывают момент
первой публикации условий. `../moex-analytics/moex_analytics/cbonds_events.py`
сохраняет версии кредитных событий, но старые выгрузки Cbonds без времени
наблюдения не являются причинным историческим источником.

Предлагаемое расширение: общий архив документов с отдельной таблицей облигационных
событий и парсером. Связь — по ISIN/регистрационному номеру выпуска и ИНН эмитента;
для обязательства нужны вид платежа, номер купона/транша, валюта и плановая дата.
Сохранять отдельно установление ставки/суммы купона, изменение условий, оферту,
амортизацию/погашение, исполнение и неисполнение, исправления. Плановая дата,
фактическое исполнение, публикация и наблюдение не взаимозаменяемы. Сообщение
эмитента об исполнении не подтверждает зачисление конкретному инвестору.

Это даст первичные доказательства для профиля погашений и проверки кредитных
событий в `moex-analytics` (см. `docs/adr/0002-g-spread-and-refinancing-risk.md`
того проекта). Сначала нужен отдельный облигационный universe из moexutils,
включая эмитентов без акций, и проверка покрытия категорий поиска. Повторно
скачивать уже закреплённые документы не требуется. Облигационный парсер и его
интеграция реализованы в `issuer_events`: [контракт и проверенная поставка](issuer-events.md).
Полный облигационный universe остаётся отдельным расширением; дивидендная схема
не выдаёт купоны за дивиденды.
