# Общий слой сообщений эмитентов

Сбор и архивирование принадлежат dividends; позиции, решения и уведомления — moex-analytics.
Слой issuer_messages не использует дивидендную семантику: купоны, суды и ПВО не исключаются.
Используется существующий dividend_events.storage.EvidenceStore: первичные байты,
SHA-256 и безопасные HTTP-метаданные. Дивидендный пакет не изменяется.

Запуск из корня dividends: `python -m issuer_messages --root PRIVATE_DATA_ROOT`.
Зависимости: requirements-events.txt. Существующий планировщик аналитики вызывает сбор
перед чтением latest.json; отдельное расписание не создаётся. Секретов Telegram здесь нет.

Контракт JSON schema_version=1: created_at, sources (охват/состояние/дата), messages.
Сообщение: message_id, issuer_inn, isins, case_numbers, source_role, title, text,
published_at (может быть NULL), observed_at, first_seen_at, content_sha256,
evidence_id/raw_path, revisions. Стабильный ID по источнику и URL; правки — новые версии.
Даты публикации и наблюдения не смешиваются. Сбой сохраняет старые записи с явно плохим
статусом источника. HTTP 200 с неверной структурой не считается успешным пустым результатом.

Первый набор: Волста /disclosure (Рубеж с точным ISIN и ИНН), официальный RSS ЕвроТранса,
последние 8 статей отдельной ленты Интерфакса по ЕвроТрансу. Это ограниченный охват,
не полная история судебных дел. Свежесть проверки не означает свежесть публикаций.
ПВО подтверждает собственное сообщение, эмитент — собственное заявление;
новость агентства — вторичный источник. Ни один не заменяет судебный акт.
Юридические сроки автоматически не рассчитываются; deadlines_verified всегда пуст.
В аналитике даты из текста передаются на проверку с контекстом, датой и источником.
КАД заблокирован, Федресурс требует проверку, e-disclosure отвечает 403: обхода нет.

Модуль использует находящийся в разработке dividend_events.storage. Его изменения
и прочие незакоммиченные материалы dividends не входят в коммит этой функции.
